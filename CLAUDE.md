# Ensign — notes for AI assistants

Controller support mod for FTL (Linux Steam 1.6.13) on Hyperspace. Read `README.md` first.

Rules of the road:
- NixOS: every tool comes from `nix develop` (flake.nix). No system compilers.
- Never modify the real game directory under `~/.steam` except through `tools/install.sh` / `tools/uninstall.sh`.
- The native shim must stay first in `LD_PRELOAD` (it interposes `luaL_newstate`).
- Hyperspace Lua has no `require`; all scripts share one environment under the `ENSIGN` table and are listed in order in `mod/data/hyperspace.xml.append`.
- Struct layouts in `native/third_party/ftl_structs_elf64.h` are layout-only; never retype fields. `OFFSETS.txt` is regenerated by `native/tools/offsets_probe.cpp`.
- Validate UI flows with `tools/run-headless.sh --script tests/<name>.txt` (dev commands documented in `mod/data/ensign/80_dev.lua`). `ENSIGN_TRACE=1` logs every native call.
- Lint Lua with `luacheck mod/data/ensign`; build native with `make -C native`.
- Prefer direct game-logic calls (`native/src/logic.cpp`, exposed as `Ensign.sysPower`, `moveCrew`, `fireAt`, ...) over emulated clicks; the click path stays only as a fallback for plain UI buttons. New entry points: look them up in `zhl.log` (Hyperspace's resolved function list) or `nm FTL.amd64`, add the mangled name to `logic.cpp`.
- Struct offsets in the header can be wrong (the Door layout was); when a field read through it never changes, dump the live bytes (`doorbytes`-style dev probe, or `dev_probe`) and compare with what Hyperspace's Lua reports before trusting it. The game's own keyboard events reach Lua through Hyperspace's `ON_KEY_DOWN` / `ON_KEY_UP`; the keyboard layer lives in `10_input.lua` (`I.KEYS`).
- Releases: `tools/package.sh [VERSION]` builds `dist/ensign-<version>-linux-x86_64.tar.gz` (portable zig build, glibc >= 2.31, checked). `.github/workflows/release.yml` runs it on the GitHub mirror: `main` replaces the `nightly` prerelease, `v*` tags make versioned releases. Steam Input files are generated (`tools/gen-steam-input.py`); CI fails if they are stale. Never commit build outputs (`build/`, `dist/`).
